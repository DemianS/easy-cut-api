# ADR 0005: полный SHA-256 checksum медиаактивов

- Статус: принято
- Дата: 2026-10-18

## Контекст

Путь не является стабильным идентификатором файла. Размер, дата изменения и
технические метаданные помогают найти кандидатов, но не доказывают равенство
содержимого. Частичный hash быстрее для больших файлов, однако может дать
ложное совпадение и требует отдельного полного подтверждения.

## Решение

- После успешного `ffprobe` задача `asset_probe` рассчитывает полный SHA-256.
- Файл читается блоками по 8 MiB и не загружается целиком в память.
- До и после расчёта проверяются размер и `modified_at_ns`, полученные при
  сканировании. Изменившийся во время анализа файл не индексируется.
- Во время долгого чтения обновляется heartbeat job.
- Алгоритм и digest сохраняются в `assets.checksum_algorithm` и
  `assets.checksum`.
- При совпадении полного SHA-256 актив получает ссылку
  `duplicate_of_asset_id` на самый ранний канонический актив, который сам не
  является дубликатом.
- Изменение файла сбрасывает checksum и производные данные; успешная повторная
  доставка завершённой job переиспользует сохранённый результат.

## Последствия

- Дубликаты подтверждаются по содержимому, а не по имени или размеру.
- Первый probe читает весь файл дополнительно к `ffprobe`, что увеличивает I/O.
- Обнаружение перемещения с переносом нового location на прежний `asset_id`
  остаётся отдельным следующим шагом; текущая версия лишь связывает найденный
  дубликат с каноническим активом.
- Частичный fingerprint можно добавить позднее только как предварительный
  фильтр, не заменяя полный checksum для подтверждения.
