# ADR 0009: Выбор клипов перед отдельным рендером

- Статус: принято
- Дата: 2026-10-20
- Дополняет ADR 0007.

## Решение

MontageCreate.auto_render=true сохраняет прежнее поведение. При false
родительская job успешно заканчивает подготовку после plan/search/select,
сохраняя stage=awaiting_selection. Ожидание человека не занимает worker,
не считается зависшей running-job и не запускает рендер при reconciliation.

PATCH /api/v1/montages/{id}/selection принимает base_version_id и список
candidate_id/duration_ms/reason. Допускается ручной выбор подмножества секций,
перестановка клипов и изменение длительности результата в пределах 1–120 s.
Backend проверяет ID по сохранённой подборке, интервалы/повторы/кадровую сетку
и создаёт новую TimelineVersion с parent_version_id, source=user, снимками
выбора и кандидатов. Текущая версия хранится явно в MontageRun. Запись run
блокируется на время проверки base_version_id и сохранения новой версии.
Устаревшая база даёт 409; содержимое старых версий не изменяется.

POST /api/v1/montages/{id}/renders принимает timeline_version_id, создаёт
MontageRender и отдельную job существующего типа montage_render. Автоматическая
ветка использует тот же контракт привязки job к версии. Повторный запрос
активной/успешной версии возвращает прежний render; после ошибки разрешена новая
попытка. Рендер использует snapshot кандидатов своей версии. Правки во время
рендера разрешены; результат старой версии не подменяет текущий.
Advisory lock рендера привязан к версии: разные попытки одного timeline
не могут одновременно перезаписывать общий рабочий каталог.

GET /api/v1/montages/{id} содержит state, текущие timeline/selection и renders.
State выводится из сохранённых этапов и render jobs: preparing,
awaiting_selection, rendering, completed, failed. JobStatus не расширяется:
успешная подготовка и рендер имеют независимые lifecycle.
GET /{id}/versions возвращает историю. GET /{id}/renders/{render_id} и /video
позволяют получить статус и файл конкретной версии; прежний /{id}/video
остаётся ссылкой на результат текущей версии.

## Миграция и ограничения

Снять unique(montage_run_id) у TimelineVersion, добавить snapshots/current ID
и таблицу MontageRender. Backfill сохраняет существующий выбор и связи уже
созданных render jobs. Старые запросы без auto_render трактуются как true.
Поисковые запросы/область на этом шаге неизменяемы: новая подборка требует
нового MontageRun. Ручная подрезка с произвольным source_start_ms и UI —
отдельные задачи; сейчас backend размещает выбранные отрезки по политике MVP.
