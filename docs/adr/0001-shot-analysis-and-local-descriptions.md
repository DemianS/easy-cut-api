# ADR 0001: планы, репрезентативные кадры и локальные описания

- Статус: принято
- Дата: 2026-10-15

## Контекст

Поиск монтажных фрагментов требует описаний конкретных временных интервалов.
Описание целого файла не позволяет понять, где именно находится нужное
действие. Исходные медиа должны оставаться неизменными, а обращения к облачным
моделям без явного разрешения запрещены.

## Решение

- Базовой единицей визуального анализа является `shot` с полуоткрытым
  интервалом `[start_ms, end_ms)`.
- Границы планов определяет отдельная задача `shot_detection` через
  PySceneDetect `ContentDetector`.
- Для каждого плана FFmpeg извлекает один средний репрезентативный кадр в
  управляемое хранилище производных артефактов. Исходный файл монтируется
  только для чтения.
- Повторная детекция обновляет текущий набор планов по порядковому номеру и не
  меняет ID совпавших записей. Лишние планы и их производные данные удаляются.
- Описание выполняет отдельная задача `asset_description`. Она обращается
  только к явно настроенному локальному Ollama-совместимому API и валидирует
  структурированный ответ Pydantic-схемой.
- Описание хранится отдельно от плана вместе с provider/model, версией prompt,
  языком, статусом и диагностикой.
- Подключение облачных provider-ов в это решение не входит.

## Последствия

- Детекцию и описание можно независимо перезапускать и диагностировать.
- Планы становятся пригодными для последующего семантического поиска по
  точным временным интервалам.
- Каталог артефактов требует отдельного writable volume worker-контейнера.
- Один кадр на план является ограничением MVP: динамичные планы позднее могут
  потребовать адаптивной выборки нескольких кадров.
- Текущая схема хранит один актуальный набор планов. Версионирование результатов
  анализа потребуется до использования планов в сохранённых монтажных листах.
